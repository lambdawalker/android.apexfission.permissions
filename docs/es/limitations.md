# Limitaciones y límites de seguridad

- Solo se admiten permisos ordinarios en tiempo de ejecución. La superposición sobre otras aplicaciones, el acceso a todos los archivos, las alarmas exactas y otros ajustes especiales requieren flujos separados de la aplicación. La biblioteca no valida si una cadena arbitraria corresponde a un permiso en tiempo de ejecución o está declarada en el manifiesto.
- Una solicitud por lotes no es atómica ni garantiza un solo diálogo del sistema. Android, el SDK de destino, las políticas del dispositivo y el comportamiento del fabricante determinan los resultados.
- El estado de los permisos no equivale a autenticación, autorización para firmar documentos ni un límite de seguridad para el código en segundo plano. El control de acceso solo controla la composición. No detiene recursos o tareas ya iniciados; la aplicación se encarga de liberarlos y de gestionar la revocación o una `SecurityException` al usar una API protegida.
- Las recetas de ubicación comprueban permisos, no si los servicios de ubicación están activados. Que las notificaciones estén listas no garantiza que un canal concreto entregue avisos.
- Las recetas no mantienen un historial de denegaciones. Una solicitud de notificaciones o de ubicación en primer plano bloqueada puede seguir devolviendo `RequestRuntime`; la aplicación debe ofrecer recuperación y evitar bucles de reintento.
- Las decisiones sobre ubicación en segundo plano comprueban el SDK y los permisos, no todas las excepciones de versiones de destino antiguas. La receta proporcionada usa solicitudes separadas de segundo plano en API 29 y Ajustes en API 30+ una vez satisfecho el acceso en primer plano. Valida por separado las combinaciones inusuales de SDK de destino.
- El selector de un solo elemento no gestiona permisos amplios de la galería. La persistencia del URI y la nueva selección de acceso a toda la biblioteca o a fotos seleccionadas corresponden a la aplicación.
- Los controles con todos los permisos opcionales no muestran una pantalla para obtenerlos. `onPermissionsResult` observa los resultados de las solicitudes, no cada cambio de permisos tras volver de Ajustes o reanudar la aplicación.
- `PermissionRequester` no proporciona cola de solicitudes, tiempo de espera, cancelación pública, continuación duradera de callbacks ni suscripción a cambios de permisos.
- Las estimaciones de lectura cuentan palabras separadas por espacios en blanco, añaden dos segundos y limitan el resultado a 4–60 segundos. No garantizan la velocidad de lectura. Usa demoras positivas explícitas para páginas con muchas imágenes o textos en idiomas sin separación de palabras.
- Las etiquetas visuales predeterminadas no constituyen un sistema completo de localización. Sustituye las etiquetas y las páginas de la aplicación. No se ha establecido un tamaño máximo cuantificado de lote ni un presupuesto de rendimiento; vincula las solicitudes a la función actual y evita decodificar imágenes grandes durante la recomposición.

Consulta [conceptos](concepts.md) para las responsabilidades y los hilos, y [recetas de plataforma](platform-recipes.md) para las ramas de sistema operativo admitidas. Actualmente, la CI en dispositivos cubre las API 29 y 35; no certifica todas las API, fabricantes, selectores reales ni configuraciones de políticas.
